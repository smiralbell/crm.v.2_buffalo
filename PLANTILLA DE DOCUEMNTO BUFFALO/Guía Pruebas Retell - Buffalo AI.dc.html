Pruebas masivas de agentes Retell con Claude

Mini tutorial paso a paso — el mismo proceso que seguimos con el agente Lucía, listo para repetir con cualquier proyecto.

Área
Desarrollo · QA
Aplica a
Agentes Retell AI
Fecha
Julio 2026
Versión
1.0

01Dale a Claude todo el contexto del proyecto

Pégale (o adjúntale) todos los documentos que definen cómo debe comportarse el agente: el guion/prompt, las condiciones de negocio, los límites, los precios, las excepciones... todo lo que tú mismo usarías para juzgar si una llamada está bien o mal.

Pídele explícitamente que se lo lea entero y te confirme que lo ha entendido antes de seguir. Cuantos más matices le des — qué NO debe decir, casos límite, excepciones raras — mejor podrá luego juzgar las pruebas.

02Dile cuántas pruebas y qué tipo de casos

Dos formas de definir la batería de casos:

  • Dársela tú: “quiero probar cliente sin garantía, importe justo en el mínimo, cliente enfadado, fuera de horario, alguien que miente sobre su hipoteca...”
  • Pedirle a Claude que las genere a partir de la documentación: “genera 50 casuísticas que cubran los casos normales, los límites y los intentos de romper el agente”.
Cantidad

Indica el número total de casos que quieres (nosotros hicimos 80). Cuantos más casos, más fiable el resultado, pero también más tiempo y coste.

03Consigue el ID del agente y la API key de Retell

En el panel de Retell AI:

  1. 1Entra en tu agente → pestaña Simulation (o el nombre equivalente en tu versión).
  2. 2El ID del agente aparece en la URL del navegador (algo como agent_xxxxxxxxxxxxx).
  3. 3La API key está en la configuración de tu cuenta de Retell (Settings → API Keys).

04Pásaselo a Claude y autoriza el uso

Escríbele algo como:

“Aquí tienes el ID del agente: agent_xxx y mi API key de Retell: key_xxx. Autorizo que lances simulaciones de prueba contra esta cuenta.”

Es importante decir explícitamente que autorizas el uso, porque son pruebas que quedan registradas en tu cuenta de Retell (aunque sean simulaciones de texto, no llamadas reales).

05Pide que cree y lance las pruebas

Con eso, Claude puede:

  • Crear cada caso de prueba directamente en Retell vía su API (usando “Simulation Testing”, si tu plan lo incluye).
  • Lanzar el lote completo y esperar a que termine de procesarse.

06Lo más importante: no fiarse del marcador automático

Retell tiene su propio “aprobado / fallado” automático, pero se equivoca mucho — en nuestro caso, 4 de cada 10 veces.

Instrucción clave a Claude

“No te fíes del pass/fail automático de Retell. Lee tú mismo cada transcripción real y compárala contra las reglas de negocio que te di, y dime en qué casos Retell se equivocó.”

Con más de 20–30 casos, Claude puede repartir el trabajo en varios sub-análisis en paralelo para no perder detalle — es normal, solo hay que esperar.

07Pide el informe en el formato que prefieras

  • Informe técnico con la tabla completa de resultados.
  • Versión explicada en plan sencillo, sin tecnicismos, para el desarrollador.
  • Detalle caso por caso, uno a uno, si quieres verlo todo.
  • Puntuación del 1 al 10 del estado del agente.
  • PDF descargable de cualquiera de los anteriores.

08Repite el proceso después de cada cambio

Cada vez que el desarrollador cambie algo en el agente (el prompt, la base de conocimiento, etc.), vuelve a lanzar la batería de pruebas — aunque sea un subconjunto — y compárala con el informe anterior. Así sabes si el cambio arregló algo sin romper otra cosa.

09Resumen en una frase por paso

1Dale todo el contexto del proyecto.
2Dile cuántas pruebas y qué casuísticas.
3Consigue el ID del agente y la API key en Retell.
4Pásaselos y autoriza el uso.
5Pide que cree y lance las pruebas.
6Pide que audite él mismo, sin fiarse del marcador de Retell.
7Pide el informe en el formato que necesites.
8Repite tras cada cambio del desarrollador.

10Nota de seguridad

Credencial sensible

La API key es una credencial sensible — trátala como una contraseña. No la subas a GitHub ni la compartas fuera de esta conversación privada con Claude.
